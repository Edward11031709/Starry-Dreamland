# Starry Dreamland｜電影級寫實 3D 升級路線

## 已確認方向
- 美術：電影級寫實奇幻 3D，深藍、紫羅蘭、銀白、暖金與柔和粉紫。
- 第一階段相機：固定斜上方俯視，先完成可玩且效能穩定的主廣場。
- 最後階段相機：自由移動、滑鼠旋轉與縮放；不得阻擋前面遊戲、資料及網站上線。
- 模型來源：只使用已有且授權清楚的 GLB/glTF 資產；不自行建模。每個資產記錄作者、來源、授權、下載日期、用途。
- 首頁入口固定為 `index.html`。未來可以把場景和遊戲模組化，但玩家網址保持穩定。

## Phase 0：保留 V4.1 穩定版
- 保留登入展示流程、三款主遊戲、星芽探索區、星塵結算及歷史紀錄。
- 現行 localStorage 僅供單一瀏覽器展示，不是跨裝置雲端帳號。
- 3D 改造先建立獨立版本或備份，不覆蓋穩定版。

## Phase 1：3D 中央廣場灰盒（固定相機）
- 建立 Three.js renderer、scene、camera、resize、資源清理及錯誤 fallback。
- 先確定地面、中央星盤、城堡、星象塔、三個入口及遠方競技館的空間配置。
- 佔位幾何只能用於比例及位置測試，最終建築必須換成已授權現成模型。
- 入口使用 raycasting 點擊；hover 顯示名稱、短說明及柔和發光。
- 原有按鈕、玩家資料及 HUD 保留為 HTML UI 疊層。

## Phase 2：模型及環境
1. 先完成城堡和中央廣場。
2. 再加入觀測塔、漂浮島、橋樑、雲海、星際競技館。
3. GLB 優先使用 Draco 或 Meshopt 壓縮；貼圖先控制在 1K/2K，避免大量 4K 貼圖。
4. 模型採 lazy loading；進入遊戲時才載入該遊戲專屬資產。
5. 限制陰影、後處理、粒子與燈光數量，提供低效能模式。

## Phase 3：遊戲逐步 3D 化
- 星座校準：將星點、路徑及星座圖層改為立體空間，沿用答案順序、計時及計分。
- 月相共鳴：月相與節拍軌道改成 3D 動態物件，保留命中窗口、Combo 與結算。
- 引力迷航：最後改成 3D 迷宮；優先沿用固定迷宮與格子路徑邏輯，避免過早加入複雜物理。

## Phase 4：自由探索（最後階段）
- 同時提供「廣場導覽（固定俯視）」及「自由探索」模式。
- 桌面：WASD 移動、滑鼠轉向、滾輪縮放、Esc 返回廣場導覽。
- 先做限制範圍的第三人稱控制，再視需要加入第一人稱。
- 使用現成角色模型及動畫，不自行建模。
- 手機提供虛擬搖桿及拖曳轉向；低效能裝置預設使用固定相機。
- 必須有碰撞邊界，避免玩家掉出島嶼或穿過建築。

## 建議技術
- 網頁入口：原生 `index.html`。
- 3D：Three.js、GLTFLoader、AnimationMixer。
- 相機：固定模式先完成；自由模式再選 OrbitControls（限制角度/距離）或自訂第三人稱控制。
- 只有碰撞、重力需求明確時才加入 Rapier 等物理引擎。
- 當 3D 模組與資產變多時，再改成 Vite 專案並將 build 輸出至 `dist/`；玩家仍只需瀏覽器網址。

## 驗收標準
- 固定相機版本在一般筆電可流暢操作。
- 首次進入不必下載所有小遊戲資產。
- 3D 模型載入失敗時仍可回退至原本 2.5D 廣場，不得白屏。
- 每個外部模型均有可核對授權。
- 自由探索可一鍵切回固定俯視相機。
