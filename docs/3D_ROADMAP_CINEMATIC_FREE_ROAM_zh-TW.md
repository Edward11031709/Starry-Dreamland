# Starry Dreamland｜電影級寫實 3D 升級路線

## 已確認方向
- 美術：電影級寫實奇幻 3D，深藍、紫羅蘭、銀白、暖金與柔和粉紫。
- 第一階段相機：固定斜上方俯視，先完成可玩且效能穩定的主廣場。
- 最後階段相機：自由移動、滑鼠旋轉與縮放；不得阻擋前面遊戲、資料及網站上線。
- 模型來源：只使用已有且授權清楚的 GLB/glTF 資產；不自行建模。每個資產記錄作者、來源、授權、下載日期、用途。
- 首頁入口固定為 `index.html`。玩家網址保持穩定。

## Phase 0：穩定版及雲端資料
- 保留登入、三款星夢遊戲、星芽探索區、星塵結算及雲端紀錄。
- Supabase 登入、RLS 與成績同步維持獨立於 3D 場景。
- 3D 失敗時，遊戲入口卡片仍可使用。

## Phase 1：3D 中央廣場第一版（本次開始）
- Three.js r187，以固定版本 CDN 載入，不要求玩家安裝 Node.js 或本機開發工具。
- 建立 WebGL renderer、scene、perspective camera、resize、資源清理及 WebGL fallback。
- 建立主浮空島、中央星盤、城堡、星象觀測塔、樹園、遠方行星、雲海及三座星門。
- 三座星門使用 Raycaster 點擊，另保留下方 HTML 遊戲卡片作為無 WebGL／鍵盤操作備援。
- 星塵、登入、排行榜及紀錄保留在原有 HTML UI 與 Supabase。
- 本版建築使用程序生成的幾何體作為 3D 空間與比例灰盒；尚未當作最終美術模型。

## Phase 2：授權模型與環境美術
1. 逐項選定現成且授權清楚的城堡、觀測塔、島嶼、橋梁、樹木與角色 GLB/glTF 模型。
2. 匯入前逐件記錄作者、來源網址、授權種類、下載日期及檔案雜湊。
3. GLB 優先使用 Draco 或 Meshopt 壓縮；貼圖控制在 1K/2K，避免不必要的 4K 貼圖。
4. 模型採 lazy loading；進入遊戲時才載入該遊戲專屬資產。
5. 限制陰影、後處理、粒子與燈光數量，提供低效能模式。

## Phase 3：遊戲逐步 3D 化
- 星座校準：將星點、路徑及星座圖層改為立體空間，沿用答案順序、計時及計分。
- 月相共鳴：月相與節拍軌道改成 3D 動態物件，保留命中窗口、Combo 與結算。
- 引力迷航：最後改成 3D 迷宮；沿用既有路徑及計分邏輯，避免過早加入複雜物理。
- 星域解碼、軌道接線先保留策略型互動介面，之後視玩法需求決定 3D 化程度。

## Phase 4：自由探索（最後階段）
- 同時提供「廣場導覽（固定俯視）」及「自由探索」模式。
- 桌面：WASD 移動、滑鼠轉向、滾輪縮放、Esc 返回廣場導覽。
- 先做限制範圍的第三人稱控制，再視需要加入第一人稱。
- 使用現成角色模型及動畫，不自行建模。
- 手機提供虛擬搖桿及拖曳轉向；低效能裝置預設使用固定相機。
- 必須有碰撞邊界，避免玩家掉出島嶼或穿過建築。

## 技術
- 網頁入口：原生 `index.html`。
- 3D：Three.js、後續需要模型時使用 GLTFLoader 與 AnimationMixer。
- 固定模式先完成；自由模式再選 OrbitControls 或自訂第三人稱控制。
- 只有碰撞、重力需求明確時才加入 Rapier 等物理引擎。
- 若 3D 模組及資產變多，再改成 Vite 專案並輸出至 `dist/`；玩家仍只需瀏覽器網址。

## 驗收標準
- 固定相機版在一般筆電可流暢操作。
- 手機能看見島嶼與三座星門，點擊目標清楚。
- 首次進入不必下載所有小遊戲資產。
- 3D 模型／WebGL 載入失敗時仍能使用原有遊戲卡片，不得白屏。
- 每個外部模型均有可核對授權。
- 自由探索可一鍵切回固定斜上方相機。
